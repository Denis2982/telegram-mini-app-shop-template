# Развёртывание и передача проекта

## Модель использования

Покупатель получает исходный код шаблона и разворачивает его для одного магазина. Это не
многопользовательская SaaS-платформа. При заказной настройке разворачивайте отдельные
приложение, базу PostgreSQL, Telegram-бота, домен и секреты для каждого магазина; не
переиспользуйте данные одного клиента для другого.

Покупатель оплачивает и обслуживает собственные хостинг, базу, домен, Telegram-бота и
платёжные сервисы. При услуге развёртывания заранее согласуйте, кто владеет учётными
записями и кто отвечает за дальнейшую эксплуатацию.

Для разработчика обычная лицензия рассчитана на один проект одного конечного заказчика:
код можно адаптировать и передать заказчику в составе проекта, но нельзя перепродавать
исходный шаблон как отдельный продукт. Условия эксклюзивного выкупа оформляются отдельно.

## Требования

- Node.js 20 или новее и npm; для Docker-варианта — Docker Compose.
- PostgreSQL, доступный приложению.
- Telegram-бот, созданный через BotFather; HTTPS-домен для production.
- Для хранения изображений на Vercel — подключённое публичное Vercel Blob-хранилище.

## Рекомендуемый недорогой вариант

Разверните приложение через Docker Compose на одном VPS. В этом варианте отдельные облачные
PostgreSQL и Blob-подписка не нужны: Compose запускает PostgreSQL рядом с приложением, а фото
сохраняются на диске сервера в Docker volume `uploads`. Нужны сам сервер и домен; HTTPS можно
настроить бесплатным сертификатом. Vercel с внешним хранилищем остаётся необязательной
альтернативой, а не требованием шаблона.

## Docker Compose

1. Создайте `.env` из `.env.example`:

   ```powershell
   Copy-Item .env.example .env
   ```

2. Сгенерируйте пароль PostgreSQL (Node.js входит в требования) и вставьте его в
   `POSTGRES_PASSWORD`. Сгенерируйте отдельные случайные значения для
   `ADMIN_API_KEY` и `TELEGRAM_WEBHOOK_SECRET`; не используйте один секрет для разных целей.

   ```powershell
   node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"
   ```

3. Заполните значения, необходимые магазину:
   - `BOT_TOKEN` — токен бота от BotFather.
   - `BOT_USERNAME` — username без `@`.
   - `TELEGRAM_MINI_APP_URL` — публичный HTTPS URL витрины.
   - `TELEGRAM_WEBHOOK_SECRET` — случайный секрет webhook.
   - `ADMIN_API_KEY` — ключ веб-админки; либо укажите Telegram ID сотрудников в `ADMIN_IDS`.
   - `ADMIN_CHAT_ID` — чат менеджеров. Узнать ID можно командой `/chatid` у бота.
   - Валюта, доставка, точки самовывоза и способы оплаты — параметры `CURRENCY_*`,
     `DELIVERY_*`, `PICKUP_POINTS`, `PAYMENT_PROVIDER_TOKEN` и `MANUAL_PAYMENT_DETAILS`.

   Не включайте `ENABLE_DEMO_MODE` в магазине клиента. Telegram Stars выключены по
   умолчанию; включайте их только для цифровых товаров. Укажите только реальные точки
   самовывоза; если `PICKUP_POINTS` пуст, вариант самовывоза в checkout скрыт. Имя магазина
   задаётся через `STORE_NAME` и не меняется в веб-админке. Значения `CURRENCY_*`, `DELIVERY_*`,
   `FREE_DELIVERY_FROM` и `PICKUP_POINTS` используются как начальные настройки; после сохранения
   параметры магазина из веб-админки переопределяют их.

4. Запустите контейнеры:

   ```powershell
   docker compose up -d --build
   docker compose logs -f app
   ```

   Compose создаст базу, выполнит миграции и запустит приложение на порту 3000.
   Перед публикацией настройте HTTPS reverse proxy или используйте платформу, которая
   предоставляет HTTPS. Не открывайте PostgreSQL в публичную сеть.

   Для уже существующей установки смена `POSTGRES_PASSWORD` в `.env` сама по себе не
   меняет пароль в ранее созданном volume базы. Сохраните текущий пароль или отдельно
   смените пароль пользователя PostgreSQL, предварительно сделав резервную копию.

## Локальная разработка

1. Установите зависимости: `npm ci`.
2. Создайте PostgreSQL базу и укажите локальный адрес в `DATABASE_URL` в `.env`.
3. Выполните `npm run db:migrate`, затем `npm run dev`.
4. Без `BOT_TOKEN` включается локальный демо-режим. Он предназначен только для разработки,
   не для открытой демонстрации или production; демонстрационные точки самовывоза не являются
   реальными адресами. В production демо-каталог автоматически не создаётся: добавьте свои
   товары через админку.

Для production-подобной проверки выполните:

```powershell
npm run lint
npm run typecheck
npm run build
```

## Vercel

1. Создайте отдельный проект и подключите PostgreSQL. Добавьте переменные из `.env.example`
   в настройки проекта и соответствующие окружения Vercel. Не добавляйте `.env` в Git.
2. Для миграций загрузите переменные целевого окружения командой
   `vercel env pull .env.local`, затем выполните `npm run db:migrate`.
3. Создайте Vercel Blob Store с публичным чтением и подключите его к проекту. Для runtime
   загрузки изображений требуется `BLOB_STORE_ID` или `BLOB_READ_WRITE_TOKEN`; на Vercel
   подключённый Blob Store выдаёт нужную конфигурацию автоматически.
4. Разверните приложение и установите webhook бота, передав `ADMIN_API_KEY` в заголовке:

   ```powershell
   curl.exe -X POST https://shop.example.com/api/telegram/setup `
     -H "x-admin-key: $env:ADMIN_API_KEY"
   ```

   Команда регистрирует webhook и кнопку Mini App. Выполняйте её после каждого изменения
   публичного URL, токена бота или языка/подписи кнопки (`DEFAULT_LOCALE`).

Названия пунктов интерфейса Vercel могут меняться; проверяйте, что переменные добавлены именно
в production environment, а не только в preview.

## Фото товаров

- Админка принимает PNG, JPG и WebP размером до 10 МБ на файл. Изображения загружаются
  отдельно от базы, а в товаре сохраняется URL.
- В Docker файлы находятся в отдельном volume `uploads`. Он переживает пересоздание
  контейнера, но удалится вместе с volume; включите его в резервное копирование.
- На Vercel нужен подключённый **Public** Blob Store. Если хранилище не подключено,
  загрузка завершается ошибкой. Загруженные изображения доступны по публичным URL.
- На других хостингах локальный каталог `public/uploads` надёжен только при постоянном
  диске, смонтированном в каталог приложения. Эфемерный диск может очиститься при
  перезапуске или новом deploy; для него используйте внешнее объектное хранилище.
- Замена фотографии или удаление товара не удаляет старый файл из Blob/volume автоматически.
  Проверяйте и очищайте неиспользуемые файлы отдельно; не удаляйте изображения, URL которых
  используются другими товарами.

## Резервное копирование и обновления

- Настройте регулярные резервные копии PostgreSQL и проверьте процедуру восстановления.
- Для Docker защищайте данные volume `pgdata` и отдельно volume `uploads`.
- Перед миграцией или обновлением сделайте резервную копию базы. Выполняйте
  `npm run db:migrate` для новой версии; не применяйте `drizzle-kit push` в production.
- После восстановления или обновления проверьте `/api/health`, оформление тестового заказа,
  уведомление в чате менеджеров и загрузку изображения.

## Чек-лист передачи клиенту

- У клиента свои Telegram bot, база, домен, секреты и платёжные реквизиты.
- Демо-режим выключен; админ-доступ проверен; тестовые ключи удалены.
- Проведён тестовый заказ и проверены уведомления, статусы, отмена и возврат остатков.
- Настроены HTTPS, резервное копирование, мониторинг и ответственность за обновления.
- Проверены имя магазина, валюта, тарифы доставки, реальные пункты самовывоза и каталог.
- Переданы инструкции доступа без пересылки секретов в открытом виде.
- Если заказана услуга настройки, письменно зафиксированы её границы и срок сопровождения.
- Переданы согласованные условия лицензии и поддержки.

В репозитории пока нет автоматического набора тестов. Перед запуском выполните lint,
typecheck и production build, затем вручную проверьте оформление, оплату, уведомления,
отмену заказа и загрузку изображений в целевой инфраструктуре.
